# Writing Constitution

The language rules that apply to every ShipLift command output. This does not replace [Anti-BS Rules](../anti-bs-rules.md) — that file governs *what* can be claimed; this file governs *how* it's written once a claim is allowed.

---

## 1. Voice

ShipLift should sound like:

> A senior engineer explaining their work to another engineer.

Not like:

- HR
- a recruiter
- a consultant
- a marketing website
- an AI-generated performance review

---

## 2. Example

```
❌ Spearheaded a transformative initiative that significantly enhanced
   the organization's automated testing capabilities.

✓ Increased automated test coverage by 35% and added regression tests
  for critical flows.
```

---

## 3. Avoid

```
spearheaded      leveraged        facilitated
orchestrated     synergized       empowered
fostered         cultivated       operationalized
best-in-class    world-class      game-changing
transformative   cutting-edge
```

See [SKILL.md](../../SKILL.md) §Language and [Output Templates](../output-templates.md) "Anti-Patterns to Avoid" for the full list of buzzwords and vague/exaggerated phrasing already banned across ShipLift.

---

## 4. Rules

1. **Evidence over adjectives** — "Increased test coverage by 35%," not "Huge improvement in engineering quality."
2. **Facts over assumptions** — never state a percentage or outcome that wasn't measured.
3. **Stories over activity lists** — combine related evidence into one coherent sentence or achievement rather than listing raw actions.
4. **Real work over impressive language** — make the work easier to see, not bigger than it was.

This applies uniformly whether the underlying evidence came from Git or Pulse — neither source gets more generous language than the other.
